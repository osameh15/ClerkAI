# Handwriting → Document — Acceptance Criteria

| Field | Value |
|---|---|
| Status | Accepted |
| Spec class | Implementation-ready |
| Version | 1.0.0 |
| Last Updated | 2026-09-28 |
| Owner | Product + QA |
| Blueprint | App. D |

| ID | Criterion |
|---|---|
| HW-AC-01 | Multiple pages from photos, scans and PDFs can be combined, reordered and excluded before submission. |
| HW-AC-02 | Low-confidence words/numbers are highlighted on the page image and reviewable (App. D "Uncertain text"). |
| HW-AC-03 | Unreadable fields never enter an official document as guessed text (App. D "No silent invention"); finalisation is blocked until resolved or explicitly marked illegible (per policy). |
| HW-AC-04 | The clean document preserves original wording (no semantic rewriting). |
| HW-AC-05 | From the same job, the user can generate a formal letter, meeting minutes and a task list without re-running OCR (no additional OCR usage). |
| HW-AC-06 | Every factual element in a generated letter is bound to Knowledge with evidence; unbound facts are flagged. |
| HW-AC-07 | Task list items can be turned into Action Items at Final. |
| HW-AC-08 | Persian RTL + Latin digits/Jalali dates render correctly in PDF/DOCX. |
| HW-AC-09 | Evaluation suite `handwriting-core` passes. |
